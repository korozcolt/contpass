## E2E Flows (3 complete, 1 partial)

1. **Quotation → Voucher → Ledger/Excel export** — ✓ Complete. `ConvertQuotationToIncome` reuses the same `PostIncomeVoucher` as every other posting path; the `decimal:2`→float cast fix in Phase 5's row-builders applies uniformly regardless of entry origin. Verified by test fixture built through the actual conversion path.
2. **ICA-withheld expense → bank reconciliation → Excel export** — ⚠ Partial. Reconciliation itself is fully agnostic to withholding/municipality and works correctly end-to-end. However the "cuentas por pagar" report/export is sourced from `BudgetObligation`, not `ExpenseRecord` — private-market expenses (always `budget_obligation_id: null` via the Filament create flow) never surface in that specific report. Pre-existing limitation (predates all 5 phases), not a regression, but relevant to this milestone's private-market focus.
3. **IncomeRecord + ExternalInvoiceReference → Ledger/AccountsReceivable reports** — ✓ Complete, confirmed no leakage. `ExternalInvoiceReference` is a fully separate table; ledger/AR queries never reference it.
4. **Cross-phase migration/model column safety** — ✓ Confirmed. All additive columns (`expense_records.municipality_id`, `external_invoice_references.*`) are nullable/uniquely-constrained with no fillable/cast conflicts found across `AccountingEntry`, `IncomeRecord`, `ExpenseRecord`, `Payment`, `WithholdingRule`.
