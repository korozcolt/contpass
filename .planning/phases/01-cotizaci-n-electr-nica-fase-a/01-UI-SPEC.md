# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This project is a Laravel 13 + Filament v5 admin panel (Livewire/Blade, not React/Next.js/Vite). The shadcn initialization gate does not apply — Filament ships its own native panel component library and design token system. This contract therefore has two surfaces to specify:
1. **Panel surface** (`QuotationResource` — form, table, actions) — governed by the *existing* Filament panel design system already locked in `AdminPanelProvider` (source of truth, not re-decided here).
2. **PDF surface** (`resources/views/pdf/quotation.blade.php`, QUOT-04) — a bespoke DomPDF-rendered document with no existing precedent in this codebase; this is the one surface in this phase that needs a genuine new visual contract.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Filament v5 native panel — not a shadcn/React project) |
| Preset | not applicable |
| Component library | Filament v5 panel components (`Schemas\Components`, `Tables\Columns`, `Actions`) — source: `app/Providers/Filament/AdminPanelProvider.php` |
| Icon library | Heroicons via `Filament\Support\Icons\Heroicon` enum (existing convention across all enums/resources) |
| Font (panel) | IBM Plex Sans — set via `->font('IBM Plex Sans')` in `AdminPanelProvider`; monospace via `->monoFont('IBM Plex Mono')` for tabular/numeric data |
| Font (PDF) | IBM Plex Sans is the brand font (loaded via Bunny CDN for the web app) but is **not** guaranteed embeddable in DomPDF without a local TTF asset. Contract: attempt to register IBM Plex Sans as a local `@font-face` in the PDF stylesheet if a TTF is vendored; if not trivially available, fall back to DomPDF's built-in `DejaVu Sans` (closest safe sans-serif, avoids DomPDF's default Serif/Times rendering which reads as "generic invoice"). Do not spend implementation time chasing pixel-perfect font matching — brand identity in the PDF comes primarily from the logo + color accent, not typeface. |
| Primary brand color | Amber (`Color::Amber`, Filament palette) — existing panel-wide decision, inherited, not re-litigated by this phase |

## Spacing Scale

Declared values (must be multiples of 4) — applies to the PDF document only; the Filament panel surface already inherits Tailwind's 4px-based spacing scale from the framework and needs no new declaration.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Line-item table cell inner padding (vertical) |
| sm | 8px | Line-item table cell inner padding (horizontal); label-to-value gaps in header block |
| md | 16px | Gap between document sections (header / third-party block / line table / totals / notes / footer) |
| lg | 24px | Page margin (top/bottom); gap above totals box |
| xl | 32px | Gap between logo block and company/third-party info block |
| 2xl | 48px | not used in this phase |
| 3xl | 64px | not used in this phase |

Exceptions: PDF page side margins set to 20mm (DomPDF default `@page` margin convention, not a 4px-multiple token — this is a physical print-margin unit, not a screen spacing token, so it is exempt).

## Typography

Panel surface: inherits Filament's built-in type scale — no new declaration needed (form labels, table headers/cells, badges all use Filament defaults already applied across every other Resource in this codebase).

PDF surface (QUOT-04) — declare explicitly since this is new:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (line items, third-party data) | 10pt | 400 (regular) | 1.4 |
| Label (field labels: "Cliente", "Vigencia hasta", table column headers) | 9pt | 600 (semibold) | 1.2 |
| Heading (section titles: "Datos del cliente", "Términos y condiciones") | 12pt | 600 (semibold) | 1.2 |
| Display (document title "COTIZACIÓN" + number `COT-2026-00001`, and grand total amount) | 18pt | 600 (semibold) | 1.2 |

Note: sizes are in `pt` (points), not `px`, per print/PDF convention — DomPDF renders CSS `pt` reliably for print output; this is the correct unit for this one surface, not a deviation from the 3-4 size rule (still exactly 4 distinct sizes, 2 weights).

## Color

PDF surface (the only surface needing new color declarations — panel surface colors below are existing precedent, listed for reference/consistency only):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (white) | PDF page background |
| Secondary (30%) | `#F5F5F4` (light neutral gray — matches Filament's `gray-100`) | Line-item table header row background, totals box background |
| Accent (10%) | Amber `#D97706` (Filament `Color::Amber` 600 — matches panel primary) | Document title "COTIZACIÓN" text, thin accent rule under the header, grand total amount emphasis. Reserved **only** for these three elements — not used on body text, table borders, or the notes/terms section. |
| Destructive | `#DC2626` (Filament `danger` red 600) | Not used in the PDF itself (PDF has no destructive actions) — reference value only, for consistency if a "Vencida"/"Rechazada" watermark-style stamp is ever added in a future phase. Not required for QUOT-04. |

Accent reserved for: document title text, header accent rule, grand total figure. Nothing else in the PDF uses amber — table borders and body text stay neutral gray/black to keep the printed document professional and legible when printed in grayscale.

### Panel surface status colors (QuotationStatus enum — QUOT-03)

Existing house convention (verified against `VoucherStatus`, `BudgetObligationStatus`, `PaymentOrderStatus`): status badges use Filament semantic color names, not raw hex, and lifecycle actions follow a consistent color-per-stage pattern already established in `PaymentOrdersTable` (`approve` = `primary`, `execute` = `success`). This phase's `QuotationStatus` and its table actions MUST follow the same convention:

| Status / Action | Filament Color | Icon (Heroicon) | Rationale |
|---|---|---|---|
| Draft (Borrador) | `gray` | `PencilSquare` | Matches `VoucherStatus::Draft`, `BudgetObligationStatus::Draft` exactly |
| Sent (Enviada) | `info` | `PaperAirplane` | Matches existing `info` usage for "in-flight/intermediate" states (`PaymentMethod::Check`, `WarehouseMovementType::Transfer`) |
| Accepted (Aceptada) | `success` | `CheckCircle` | Matches `VoucherStatus::Approved`, `BudgetObligationStatus::Approved` |
| Rejected (Rechazada) | `danger` | `XCircle` | Matches `VoucherStatus::Void`, `BudgetObligationStatus::Cancelled` |
| Expired (Vencida, computed) | `warning` | `ClockIcon`(`heroicon-o-clock`) | Matches `VoucherStatus::Adjusted`'s use of `warning` for a "needs attention" terminal-adjacent state |
| Converted (Convertida) | `primary` (amber) | `CheckBadge` | Distinct from `success`/Accepted so the table is scannable at a glance between "approved, awaiting conversion" and "already posted to accounting" — mirrors `PaymentOrdersTable`'s `approve` action using `primary` for the mid-lifecycle progression step |
| "Enviar" row action | `primary` | `PaperAirplane` | Matches `PaymentOrdersTable::approve` convention (primary = intermediate lifecycle transition) |
| "Aceptar" row action | `success` | `CheckCircle` | — |
| "Rechazar" row action | `danger` | `XCircle` | — |
| "Convertir a ingreso" row action | `success` | `Banknotes` | Matches `PaymentOrdersTable::execute` convention (success = final, money-creating action) |
| "Descargar PDF" row/page action | `gray` (default/no override) | `DocumentArrowDown` | Neutral utility action, not a lifecycle transition — do not use primary/accent here to keep the PDF download visually distinct from state-changing actions |

## Copywriting Contract

All copy in Spanish (`es_CO`), matching existing house style (see `VoucherStatus::label()`, existing `emptyStateHeading`/`emptyStateDescription` calls across `app/Filament/Pages/*Report.php`).

| Element | Copy |
|---------|------|
| Primary CTA (create) | "Nueva cotización" (`CreateAction` label, matches existing `Crear`-prefixed but noun-first pattern seen in other List pages) |
| Primary CTA (conversion, table row action) | "Convertir a ingreso" — per QUOT-05/CONTEXT.md, must read as a single decisive action, not "Convertir" alone |
| Primary CTA (lifecycle) | "Enviar" / "Aceptar" / "Rechazar" — one verb each, matches `PaymentOrdersTable` convention (`Aprobar`, `Ejecutar pago`) |
| Empty state heading | "No hay cotizaciones" (matches exact phrasing pattern of `WarehouseStockReport`: "No hay elementos registrados", `JournalReport`: "No hay comprobantes") |
| Empty state body | "Crea una cotización para un tercero desde el botón 'Nueva cotización'." (matches action-oriented pattern of `WarehouseStockReport::emptyStateDescription`: "Crea elementos en Catálogos → Elementos para ver su stock aquí.") |
| Error state (numbering race / concurrency guard) | "No se pudo generar el número de cotización. Intenta nuevamente." — generic per house convention (services throw `ValidationException`/`RuntimeException` with user-facing Spanish messages, e.g. `PostsBalancedVoucher`'s pattern; no raw exception text ever shown) |
| Error state (double conversion guard, QUOT-06) | "Esta cotización ya fue convertida o no está Aceptada." — reuses the exact message already drafted in RESEARCH.md Pattern 2, confirmed as the validation message for `ConvertQuotationToIncome` |
| Error state (rejection reason required, D-06) | "Debes indicar un motivo de rechazo." — required-field validation message, shown inline under the `rejection_reason` field, not as a toast |
| Destructive confirmation ("Rechazar") | Action: Rechazar cotización. Confirmation: modal form (not a bare confirm dialog) requesting the mandatory reason field — "Vas a marcar esta cotización como Rechazada. Indica el motivo:" — matches `PaymentOrdersTable::execute`'s existing pattern of using `modalHeading`/`modalDescription` + inline form instead of a yes/no confirm for any lifecycle action that requires data capture |
| Destructive confirmation ("Convertir a ingreso") | No form needed (D-05: accounts already on the quotation) — but per house convention for irreversible actions, use `->requiresConfirmation()` with modal copy: "Esta acción creará un comprobante de ingreso contable y no se puede deshacer. ¿Continuar?" |
| PDF: no-notes state | Terms/notes section is omitted entirely (not shown as empty) when `notes` is blank — per D-02 ("se imprime solo si tiene contenido") |
| PDF: expired quotation | If a user downloads the PDF of a `Vencida` (expired) quotation, no special watermark/copy is required for v1 — the PDF header still reads "COTIZACIÓN" with its original validity date printed as-is (out of scope per CONTEXT.md; do not invent a "VENCIDA" stamp not requested) |
