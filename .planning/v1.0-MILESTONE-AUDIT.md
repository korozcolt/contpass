# Milestone v1.0 Re-Audit — Mejoras Comerciales para Mercado Privado

**Audited:** 2026-09-19 (re-audit after Phases 6-7 gap closure)
**Status:** gaps_found — one new, non-critical UI-reachability gap discovered; both originally-flagged gaps from the 2026-09-18 audit are confirmed closed

## Summary

This is a re-audit run after closing the two non-critical gaps found by the 2026-09-18 audit (orphaned ReteICA legacy code via Phase 6; private-market accounts-payable scope via Phase 7). Both original gaps are **confirmed closed** by independent code re-verification (not just re-reading prior VERIFICATION.md claims): the orphaned `WithholdingRuleController`/`StoreWithholdingRuleRequest`/blade views are gone with zero dangling references, and `AccountsPayable::openItems()` now correctly combines public `BudgetObligation` rows with private-market `ExpenseRecord` rows at the service/CSV/Excel layer.

However, this re-audit's integration check — which specifically re-verified the full E2E chain for AP-01 including the Filament UI page (not just the service/CSV/Excel layer the original audit and Phase 7's own verifier checked) — found a **new, previously-undetected gap**: `AccountsPayableReport::canAccess()` gates the entire Filament report page behind `has_budgetary_control === true`, which is the opposite of the flag that gates private-market `ExpenseRecord` creation (`ExpenseRecordResource::canCreate()` requires `has_budgetary_control === false`). The two conditions are mutually exclusive — no company can both create the private-market expenses Phase 7 added support for AND view them on the Cuentas por Pagar screen. The page's hardcoded "obligaciones presupuestales" copy would also read wrong for private-market users even if access were opened.

This was missed by Phase 7's own plan-checker and verifier because CONTEXT.md's Integration Points section (written during discuss-phase) explicitly said the Filament page "no requiere cambios" — true for its *table/query* wiring, but nobody checked its `canAccess()` gate, since neither the original milestone audit nor Phase 7's discussion touched authorization/visibility rules. Phase 7's own test suite exercises `AccountsPayable::openItems()` directly and the Filament page only in its already-`has_budgetary_control: true` fixture — so the 403 path was never exercised by any test in either phase.

**All 24 original v1 requirements remain satisfied** (unchanged since the 2026-09-18 audit — Phases 6 and 7 touched no code in their paths). TECHDEBT-01 is fully satisfied. AP-01 is **partial**: correct end-to-end for direct-URL/API use, not reachable through the in-app UI for its target audience.
