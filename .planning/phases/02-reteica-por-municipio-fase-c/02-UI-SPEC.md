# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase extends three existing Filament v5 admin-panel surfaces (`WithholdingRuleForm`/`WithholdingRulesTable`, `ExpenseRecordForm`) and introduces one new enum (`WithholdingType`) with badge styling. It does **not** introduce a new page, layout, or visual language — every element below is a prescriptive extension of Filament's built-in component library and the codebase's existing enum/badge/select conventions (`VoucherType`, `PaymentMethod`, `AccountingFormFields`). No shadcn/React stack is present or applicable; this is a Livewire 4 + Filament 5 + Tailwind CSS 4 admin panel.

## Color

Governed by Filament's default panel palette plus the one custom primary color already configured in `AdminPanelProvider` (`Color::Amber`). This phase does not add new global colors — it assigns existing semantic badge colors to the new `WithholdingType` enum, following the exact pattern of `VoucherType`/`PaymentMethod`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Gray-50 `#F9FAFB` (light) / Gray-950 `#030712` (dark) | Filament panel background — unchanged |
| Secondary (30%) | White `#FFFFFF` (light) / Gray-900 `#111827` (dark) | Card/table/form surfaces — unchanged |
| Accent (10%) | Amber-500 `#F59E0B` (`Color::Amber`, panel `primary`) | Reserved for: primary submit buttons ("Crear regla de retención", "Guardar cambios"), active/focused form field ring, active navigation item under "Catálogos". **Never** used for the `WithholdingType` status badges below — that would blow the 10% budget. |
| Destructive | Red-500 `#EF4444` (Filament `danger`) | Reserved for: `DeleteBulkAction` confirmation modal (existing, unchanged), and the D-08 overlap validation error (red border + red helper text under `starts_on` on `WithholdingRuleForm`) |

Accent reserved for: primary CTA buttons, focused input ring, active nav item only — explicitly not for badges, icons, or decorative elements.

### New badge color assignments (`WithholdingType` enum — prescriptive, for `HasColor`/`HasIcon`/`HasLabel`)

| Case | Label (`getLabel()`) | Badge color (`getColor()`) | Icon (`getIcon()`) |
|------|----------------------|------------------------------|---------------------|
| `ReteFuente` | "Retención en la fuente" | `info` (blue) | `Heroicon::ReceiptPercent` |
| `ReteIVA` | "Retención de IVA" | `gray` | `Heroicon::CurrencyDollar` |
| `Ica` | "ICA" | `warning` (amber-adjacent semantic token, distinct from the `primary` accent) | `Heroicon::MapPin` (signals the new geo/municipality dimension) |

Rationale: keeps the 10%-accent budget intact (badges never reuse `primary`), and gives ICA a visually distinct, location-flavored icon since it is the only type with a municipality dependency — consistent with `VoucherType`'s existing pattern of one color+icon per case.

## Interaction Contract (phase-specific, beyond generic copywriting)

- `WithholdingRuleForm`: `Select::make('type')` uses `->options(WithholdingType::class)->native(false)->live()->required()`. The `municipality_id` `Select` uses `->visible(fn (Get $get): bool => $get('type') === WithholdingType::Ica)` and `->required(fn (Get $get): bool => $get('type') === WithholdingType::Ica)` — compare against the enum case directly, **never** `->value` (Filament v5 known bug, `docs/roadmap-apolo.md` issue #1). Toggling `type` away from `Ica` must clear any previously-selected `municipality_id` (`->afterStateUpdated(fn (Set $set) => $set('municipality_id', null))` on the `type` field) so a stale municipality never silently persists on a non-ICA rule.
- `WithholdingRuleForm`: the `concept` free-text field is removed (replaced by `type`). Per RESEARCH.md Open Question 2, add a supplementary optional `TextInput::make('description')->label('Descripción (opcional)')->maxLength(255)` to preserve human-readable sub-labels (e.g. "Servicios 2026") without conflating it with the filtering discriminator. This is a UI recommendation for the planner to confirm at plan time — flagged, not silently defaulted.
- `WithholdingRulesTable`: replace the `concept` `TextColumn` with `TextColumn::make('type')->label('Tipo')->badge()->sortable()`, and add `TextColumn::make('municipality.name')->label('Municipio')->placeholder('—')->toggleable()` immediately after it (empty/placeholder for non-ICA rows, per RETICA-05 — no visual noise for rules that don't have a municipality dimension).
- `ExpenseRecordForm`: `municipality_id` `Select` is always visible in the `Grid::make(2)` (per D-07, not conditional on account type), defaults via closure to the `Municipality` resolved from the current `Company`'s `dane_department_code`/`dane_municipality_code`, `searchable()->preload()`, **not** `required()` (an expense with no ICA-eligible rule for its municipality must still save — RETICA-04/05 must never block unrelated causations).
- Municipality selects (`WithholdingRuleForm` and `ExpenseRecordForm`) render as a flat `searchable()->preload()` list labeled `"{municipality.name} ({department.name})"` — matches RESEARCH.md Pattern 4, consistent with the existing `thirdParty()`/`chartAccount()` select style in `AccountingFormFields`. A two-step department→municipality cascade is explicitly **not required** for this phase (flat searchable list is sufficient and matches existing UX conventions at this data scale).
